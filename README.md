# Botna — Smart Automation / بوتنا — الأتمتة الذكية

## الإصدار 0.20.0 — هوية جديدة، ترحيب أول مرة، مساعدة محلية، ولغتان

- تحديث أيقونة التطبيق إلى هوية رسومية جديدة، مع موارد launcher لأحجام الكثافة المختلفة وأيقونات Android Adaptive Icons. يضبط Android 12+ شاشة افتتاحية تستخدم أيقونة Botna.
- أضيفت مقدمة أول تشغيل ببطاقات زجاجية وانتقال متحرك بين الشاشات، تشرح بدء الاستخدام والصلاحيات والتعامل مع لقطات الشاشة؛ تظهر مرة واحدة ويمكن تخطيها.
- أضيف اختيار لغة في رأس الواجهة الرئيسية وداخل لوحة الفقاعة: العربية والإنجليزية. يُحفظ الاختيار، وعلى Android 13+ يُزامن مع إعداد لغة التطبيق في النظام. الترجمة تغطي الشاشات الرئيسية، الأزرار، أغلب العناوين الشائعة وإعدادات المزوّد؛ قد تظل بعض رسائل الفشل المتخصصة أو بيانات السكربت التي كتبها المستخدم بلغتها الأصلية.
- يظهر اسم المطوّر «يحيى النباهين» ومعرّف Telegram `@yahea21` في أعلى الشاشة الرئيسية، مع رابط تواصل، ويوجد أيضًا قسم اتصال في أسفل الصفحة.
- أضيف مساعد استخدام محلي في الواجهة الرئيسية يشرح كيفية استخدام السكربتات، الوكيل، إعدادات API، مكتبة الصور، السجلات، خدمة إمكانية الوصول والخصوصية دون استهلاك حصة API للأسئلة الشائعة.
- حسّنت أنماط الزجاج الداكن والحدود المتباينة للأزرار والبطاقات، وأضفت رموزًا وظيفية إلى الأزرار والعناوين، ورفعت تباين نتائج البحث لتظهر بوضوح على خلفية زرقاء.
- أُعيد تصميم خلفيات AlertDialog لتناسب الواجهة الزجاجية؛ قوائم السجلات ورسائل الوكيل والمهام تستخدم ارتفاعًا متكيفًا ومنطقة تمرير مع مساحة أسفل القائمة، كما أصبحت تفاصيل سجل الفشل داخل ScrollView حتى لا تختفي النصوص أسفل الأزرار.
- أضيف إعداد `locale_config.xml` وموارد `values-en` لتوفير اختيار لغة التطبيق في إعدادات Android 13+، مع بقاء اختيار داخل التطبيق متوافقًا مع الأجهزة الأقدم.
- أضيف ملف `PRIVACY.md` كمسودة إشعار خصوصية مبنية على المصدر؛ يجب مراجعته واستضافته كرابط عام ومطابقته مع نسخة APK النهائية قبل النشر في المتاجر.

# Botna — الأتمتة الذكية

## الإصدار 0.19.0 — إصلاح النوافذ، سياق التطبيق، فهم العربية وإعادة المحاولة

- ثُبّتت أزرار «حفظ وخروج» و«إلغاء» خارج منطقة التمرير في حوارات الأتمتة؛ تبقى متاحة أثناء صعود لوحة المفاتيح، ويصبح محتوى النافذة قابلاً للتمرير بدل دفن خياراتها أسفل الشاشة.
- أُعيد بناء بحث الأوامر في نافذة وصول مستقلة مع ارتفاع مرن للنتائج، شريط إغلاق ثابت، وتركيز البحث بعد الفتح. اختيار الأمر يغلق البحث ثم يستدعي الإجراء المقابل دون إزالة لوحة الأتمتة الأصلية.
- تُعدّل مواضع كرة التحكم وشريط حالة الخطوة تلقائيًا عند ظهور لوحة المفاتيح، مع إمكانية طي شريط الحالة إلى دائرة صغيرة تتحرك فوق كرة التحكم.
- توسّع المحلل المحلي صيغ اللهجة الفلسطينية ومقدمات الأمر، ويعالج طلبات القراءة المعلوماتية: يمكنه فتح بحث ويب صريح ثم قراءة النص الذي تعرضه شجرة إمكانية الوصول، أو قراءة النصوص المرئية الحالية. لا يختلق نتيجة عندما لا يظهر نص قابل للقراءة، ولا يخمن إحداثيات عنصر بناءً على وصف شكلي دون لقطة موثوقة.
- أُضيف ملخص سياق آمن للنموذج عن قدرات Botna، الإعداد النشط، عدد المفاتيح المحفوظة، عدد قوالب الصور، إعداد حفظ صور السجلات، إصدار Android، والسكربت الحالي وخطواته. لا تُرسل مفاتيح API أو أسرار التخزين إلى النموذج.
- تُعرض في مراجعة الشروط/التكرار أعداد علامات النهاية الناقصة. يُكمل المحلل المحلي العلامات المفقودة لتجنب بنية مكسورة، مع تحذير واضح بضرورة مراجعة موضعها قبل التشغيل.
- يحاول الوكيل إعادة التخطيط بعد أخطاء المعدل المؤقتة (`429`/`503`/`408`) بمهلة أُسّية محدودة وعشوائية بسيطة، بحد أقصى 4 محاولات آلية و90 ثانية لانتظار المحاولة الواحدة. لا يعيد محاولات الحصة اليومية/المشروع أو أخطاء الفوترة/المفاتيح غير الصالحة.
- الوكيل يتخذ قرارًا واحدًا في كل دورة ويأخذ لقطة شاشة حديثة بعد كل إجراء. هذا ليس بث فيديو مستمرًا؛ أي بث عبر `MediaProjection` يتطلب موافقة صريحة من المستخدم وخدمة أمامية صالحة لنظام Android.

## الإصدار 0.18.0 — إصلاح بناء السكربتات والبحث السريع عن الأوامر

- أُضيفت دالة `BotnaStore.renameScript(Context, String, String)` إلى ملف التخزين نفسه؛ يجب رفع هذا الملف مع `MainActivity.java` حتى لا يفشل بناء GitHub Actions برسالة `cannot find symbol renameScript`.
- أُضيف زر بحث صغير بجانب أزرار بدء السكربت والإيقاف/الاستكمال والإيقاف النهائي. يفتح قائمة بحث فورية في كتالوج الأوامر الحالي، ويُظهر الأوامر المطابقة أثناء الكتابة.
- يدعم البحث ألفاظًا شائعة ولهجات عربية ومترادفات لأوامر مثل الكتابة والنقر وEnter/بحث وفتح التطبيق والرابط والتمرير والسحب والإشعارات وقياس سرعة الإنترنت. اختيار نتيجة يستدعي نفس إجراء الزر الأصلي، بما في ذلك طلب الإعدادات عند الحاجة.

## الإصدار 0.17.0 — مكتبة سكربتات منفصلة وتحكم جانبي وتحسين Enter/بحث

- أصبحت إدارة السكربتات قسمًا مستقلًا في الواجهة الرئيسية، مع عرض العدد وفتح قائمة إنشاء السكربت، فتح محرره لإضافة/تعديل الخطوات، إعادة التسمية، التشغيل والحذف.
- «×» ثم «حفظ وخروج» يحفظ التعديلات ويزيل لوحة الأتمتة وفقاعتها B معًا.
- أزرار بدء التنفيذ والإيقاف المؤقت/الاستكمال والإيقاف النهائي مثبتة أعلى لوحة الأوامر، وأثناء التشغيل تظهر كرة تحكم جانبية نصف مخفية مع أزرار دائرية عند لمسها. تتحرك الفقاعة العادية بالسحب وتنجذب إلى أحد جانبي الشاشة بحركة قصيرة، ويُحفظ الجانب والموضع.
- أزيلت الحدود الصغيرة المصطنعة عن عدد محاولات المطابقة والتكرارات. نسبة تطابق الصورة تقبل 0–100 بالمئة، بينما عدد التكرار/المحاولات يقبل أي عدد صحيح موجب ضمن نوع البيانات الصحيح المستخدم من Java.
- تحسين Enter/بحث عبر تجربة إجراء IME على الحقل المركّز، وفحص نافذة لوحة المفاتيح نفسها، ثم البحث عن زر قابل للنقر في شجرة إمكانية الوصول. لا يجري النقر العشوائي على نصوص الصفحة عند عدم العثور على زر مناسب.
- مهمة الوكيل تقبل الأهداف المعلوماتية مثل «اختبر سرعة النت وأخبرني بالنتيجة» و«افتح الرابط ولخّص محتواه». الخلاصة والنتيجة الفعلية تُحفظ في رسائل الوكيل والسجلات، وتُرفق لقطة تشخيصية إذا كان حفظ الصور مفعّلًا. لا يختلق الوكيل نتيجة لا تدعمها الشاشة أو الاستجابة.


## الإصدار 0.16.0 — تحكم جانبي، حدود قابلة للضبط، وإجابات الوكيل

- أُبقيت قائمة «السكربتات المحفوظة وإدارتها» في الواجهة الرئيسية، وتدعم إنشاء السكربت وفتح محرره لإضافة الخطوات/تعديلها وإعادة التسمية والتشغيل والحذف.
- أزرار التشغيل والإيقاف المؤقت/الاستكمال والإيقاف النهائي ثابتة في أعلى لوحة الأوامر، وتظهر أثناء التشغيل كفقاعة جانبية قابلة للسحب مع أدوات دائرية حولها.
- عند ضغط «×» ثم تأكيد «حفظ وخروج» يتم حفظ السكربت وإغلاق لوحة الأوامر والفقاعة B معًا.
- أُزيلت الحدود الصغيرة المصطنعة عن عدد محاولات الصور والتكرارات؛ نسبة التطابق قابلة للتعيين من 0 إلى 100 بالمئة، لأن النسبة لا معنى لها خارج هذا المجال. يدعم العدد الصحيح حتى حدّ نوع البيانات المستخدم في النظام.
- تحسين إرسال Enter/بحث: يفحص التطبيق إجراء IME على الحقل المركّز، ثم نافذة لوحة المفاتيح (TYPE_INPUT_METHOD)، ثم أزرار البحث والإرسال المكشوفة في شجرة إمكانية الوصول. قد تبقى بعض التطبيقات/لوحات المفاتيح الخاصة غير قابلة للتحكم إذا لم تعرض إجراءً قابلًا للوصول.
- الطلبات المعلوماتية، مثل قياس سرعة الإنترنت أو معرفة محتوى صفحة، تسجل الخلاصة النصية في رسالة الوكيل وسجل النتائج مع لقطة تشخيصية عندما يكون حفظ الصور مفعلًا. لا تُختلق نتائج لم تُقرأ فعليًا من الشاشة.


نسخة محدثة من مشروع Botna لأتمتة خطوات الهاتف عبر خدمة إمكانية الوصول ومطابقة الصور باستخدام OpenCV.

## الإصدار 0.15.0 — تثبيت أزرار الإعدادات وتحسين مشاركة الصور والوكيل المحفوظ

- واجهة إعدادات مزوّدي الذكاء الاصطناعي تستخدم الآن شريط إجراءات ثابتًا خارج منطقة التمرير: «حفظ الإعدادات» و«مسح مفاتيح المزوّد» و«إغلاق» تبقى منفصلة عن الحقول وتتحرك منطقة المحتوى مع لوحة المفاتيح. يُسحب حقل الرابط أو النموذج أو المفتاح تلقائيًا إلى مجال الرؤية عند التركيز عليه.
- واجهتا إنشاء المهمة الذكية وتحريرها تعرضان أزرار بدء/حفظ/إلغاء في شريط ثابت، مع تمرير تلقائي إلى حقل الكتابة لتقليل تغطية لوحة المفاتيح.
- لقطات الذكاء الاصطناعي تُصغّر بنسبة الأبعاد إلى حد أقصى 1440 بكسل على الجانب الأطول وبجودة JPEG 64 لتقليل بيانات النقل مع الحفاظ على تفاصيل أفضل من المصغرات شديدة الصغر. لا يمكن استعادة التفاصيل التي تُفقد بالتصغير؛ لذلك تُعاد الإحداثيات كنسب مئوية من أبعاد الشاشة الأصلية وتُحوّل إلى إحداثيات الجهاز عند التنفيذ. التثبيتات الجديدة تستخدم افتراضيًا `gemini-3.8-flash` وفق قائمة النماذج الرسمية الحالية؛ لا يتم استبدال اسم نموذج محفوظ يدويًا أثناء التحديث.
- عند أخطاء 429/الحصة، تُحفظ مهلة تهدئة لكل مفتاح، ويُحترم وقت «إعادة المحاولة بعد» إذا أرسله المزود. لا يضمن تعدد المفاتيح زيادة الحصة إذا كانت جميعها ضمن المشروع نفسه؛ Gemini يطبق حصصه على مستوى المشروع، وليس على كل مفتاح مستقل.
- المهام الذكية محفوظة في قائمة مستقلة، وكل مهمة ترتبط بسكربت Botna مستقل يمكن فتحه وتعديل بلوكاته أو تشغيل الإجراءات المحفوظة لاحقًا. رسائل الوكيل تبقى في قائمة منفصلة وتشمل سبب القرار، والإجراء المقترح، ونتيجة التنفيذ، وأسباب التوقف.
- الربط الآلي بتطبيقات Gemini/ChatGPT الاستهلاكية ليس بديل API مدعومًا في هذا الإصدار: لا توجد واجهة عامة مضمونة تُمكّن Botna من إرسال صورة إلى واجهة التطبيق واستخراج إجابة آلية منظمة منها ثم مواصلة التنفيذ. استخدام واجهة التطبيق يدويًا لا يُعفي من حدودها أو يضمن استرجاع الرد للتطبيق.

## الإصدار 0.13.0 — سجل التشخيص والوكيل المتفاعل

- إصلاح محرّر الأمر المخصص: أصبحت أزرار «تحليل وحفظ» و«إلغاء» جزءًا ثابتًا أسفل منطقة تمرير المحتوى، فلا تعتمد على أزرار الحوار الافتراضية التي قد تختفي خلف لوحة المفاتيح.
- إصلاح فتح إعدادات بلوكات الخطوات: يُغلق محرر البلوكات قبل عرض إعدادات البلوك كي لا تتراكب نوافذ إمكانية الوصول، ثم يعاد بناء قائمة البلوكات بعد التعديل.
- إضافة «قائمة السجلات» إلى الشاشة الرئيسية. تحفظ سجلات الفشل المصدر والخطوة والسبب والتفاصيل، وتربط لقطة شاشة تشخيصية عند تفعيل حفظ الصور؛ يمكن عرض التفاصيل وحذف سجل بعينه أو حذف جميع السجلات، وتعطيل لقطات التشخيص.
- تُحفظ السجلات ولقطاتها في مساحة التطبيق الخاصة، بحد أقصى 100 سجل، وتُصغّر صور التشخيص لتقليل مساحة التخزين.
- إضافة دعم عدة مفاتيح API لكل مزود، تُدخل مفاتيحها الجديدة في أسطر منفصلة وتُشفّر باستخدام Android Keystore. يعرض محرر المزود عدد المفاتيح المحفوظة والجديدة، ويجرب مفاتيح أخرى تلقائيًا عند أخطاء الحصة/التقييد/المصادقة المدعومة. لا يستطيع هذا تجاوز حصص حساب المزوّد أو ضمان استمرار الخدمة عند نفاد حصص جميع المفاتيح.
- إضافة «إنشاء بوت ذكي للمهام المعقدة»: يقرأ لقطة الشاشة، يقترح إجراءً واحدًا، ينفذه عبر أنواع الأوامر المسموحة، ثم يقرأ الشاشة من جديد لاتخاذ الخطوة التالية. الحد الوقائي 40 إجراءً لكل مهمة، وتظهر النتيجة في سجلات التشخيص. يحتاج إلى Android 11+ ومزود API يدعم الصور ومفتاح صالح.
- لا تنفذ الأتمتة عمليات الدفع والشراء وحذف البيانات أو إرسال الرسائل الخارجية تلقائيًا وفق تعليمات المترجم؛ راجع الشاشة والنتيجة بنفسك. الوكيل لا يمتلك تحكمًا غير محدود خارج واجهات أندرويد والأوامر المدعومة.

## أساسيات الإصدار 0.12.0 — الأتمتة ومحرر البلوكات

- عند تشغيل السكربت تختفي لوحة التحرير والفقاعة العائمة ولا تعودان حتى انتهاء السكربت أو إيقافه نهائيًا. تظهر لوحة تحكم زجاجية صغيرة للإيقاف المؤقت/الاستكمال، وإعادة التشغيل من البداية، والإيقاف النهائي. تُخفى عناصر التحكم مؤقتًا أثناء التقاط الشاشة وتنفيذ الإيماءات حتى لا تغطي الهدف أو تدخل في لقطة المطابقة. يترك التنفيذ نافذة تحكم لا تقل عن 250 مللي ثانية بين الأفعال، أو المدة الأطول التي تضبطها في إعداد «انتظار بعد التنفيذ».
- تنفيذ الخطوات بالتسلسل مع مراعاة التأخير قبل الخطوة وبعدها، ومحاولات مطابقة الصور وفاصل إعادة المحاولة. تُفحص بنية الشروط وكتل التكرار قبل البدء، ويُرفض تشغيل السكربت إذا كانت علامات البداية/النهاية غير متطابقة. لا تعود لوحة التحرير حتى ينتهي السكربت أو يتوقف نهائيًا.
- إعدادات مستقلة لأنواع الخطوات: مطابقة الصور، النقر على نص، الانتظار، النقر بالإحداثيات، الضغط المطوّل، السحب، التمرير، كتابة النص، الرجوع، والرئيسية، مع كتل تكرار متداخلة محدودة حتى 1000 مرة.
- خطوة الصورة تدعم عرض الزوايا المحفوظة وحذف زاوية بعد التأكيد، وإضافة زاوية أخرى، وتغيير الهدف، وتغيير نسبة التطابق، وعدد المحاولات، والتأخيرات، وخيار العثور على الصورة دون الضغط عليها.
- اختبار خطوة منفردة من قائمة الإعدادات المطوّلة؛ الاختبار ينفّذ الفعل الخاص بالخطوة أو يفحص منطق الخطوة الشرطية.
- نسخ الخطوة أو قصّها أو نقلها، ثم لصق نسخة فوق موضع محدد عبر الضغط المطوّل على بطاقة الخطوة.
- محدد النقاط وقص الصور يستخدمان تخطيطًا كامل الشاشة ويتجاهلان هوامش النظام قدر الإمكان، بما فيها منطقة ثقب الكاميرا؛ ويجب التحقق من اللمس والحواف على كل جهاز.
- عند تحليل خطوة مخصصة، يُحفظ النص الأصلي أولًا، ثم تُخفى نوافذ Botna ولوحة المفاتيح قبل التقاط لقطة السياق، وتبقى الواجهات مخفية حتى اكتمال التحليل.
- تعرض الخطوة المخصصة المترجمة كل أمر في بطاقة/بلوك مستقل يمكن فتح «تغيير الإعدادات» منه لضبط الانتظار ودقة مطابقة الصور والمحاولات والنص والإحداثيات وغيرها.
- يتضمن المحلل المحلي قواعد أوسع للهجة العربية لأوامر فتح التطبيقات والروابط والبحث والكتابة والنقر والانتظار والتمرير والإشعارات والإعدادات السريعة والتطبيقات الأخيرة ومسح حقل الإدخال. لا ينفذ العبارة غير المدعومة بصمت، بل يحفظ النص ويصدر تحذيرًا محددًا.
- إعدادات DeepSeek وOpenRouter وGroq منفصلة، ولكل منها رابط ونموذج ومفتاح محفوظ على حدة، مع أزرار «روابط» لاختيار نقاط الاتصال المعروفة و«النماذج» لجلب معرفات النماذج من API. جلب القوائم يتطلب إنترنت ومفتاحًا صالحًا.
- انتظر النظام تلقائيًا لفترات محافظة بحسب نوع الخطوة، ويمكن تحرير التأخيرات ودقة المطابقة وعدد المحاولات من بلوكات الترجمة.
- حفظ موضع التمرير في قائمة الخطوات لكل سكربت، والحفظ المحلي للسكربتات والتعديلات في التخزين الدائم للتطبيق.
- إضافة تأكيد قبل حذف الخطوة أو زاوية صورة، وتأكيد «حفظ وإغلاق» للوحة، وتأكيد عند الخروج من شاشة التطبيق بزر الرجوع.

## الاستخدام

1. افتح Botna وفعّل خدمة إمكانية الوصول من إعدادات أندرويد.
2. افتح التطبيق المطلوب واضغط الفقاعة **B** لإظهار محرّر السكربت.
3. أضف الخطوات واضغط على بطاقة خطوة لفتح إعداداتها. اضغط مطولًا على بطاقة لنسخها أو قصّها أو نقلها أو لصق فوقها.
4. اضغط «تشغيل». تختفي لوحة التحرير وتظهر أدوات التحكم المختصرة؛ زر «استكمال» يكمل عند حدّ الخطوة التالي بعد انتهاء الإجراء الجاري، و«من البداية» يعيد تشغيل السكربت، و«إيقاف» ينهي التشغيل. لا يمكن إلغاء إيماءة أندرويد بعد بدء إرسالها، لذلك يصبح الإيقاف المؤقت نافذًا بعد انتهاء الإجراء الجاري.
5. تُحفظ التعديلات تلقائيًا في مساحة التطبيق الخاصة. لا تُخزَّن السكربتات على خادم خارجي.

## المتطلبات والحدود المعروفة

- المشروع يستخدم Java 17 وAndroid Gradle Plugin 8.13.2 وSDK 36 وOpenCV 4.13.0، والإصدار الحالي 0.20.0.
- الحد الأدنى المعلن في المشروع Android 8.0 (API 26). التقاط الشاشة لقصّ الصور ومطابقتها من خلال واجهة Accessibility يتطلب Android 11 (API 30) أو أحدث.
- مطابقة الصور بصرية وليست OCR؛ قد تتأثر بدقة الشاشة، والرسوم المتحركة، وتغير شكل الهدف أو الإضاءة، لذلك اختبر كل خطوة على جهازك واضبط نسبة التطابق.
- «اختبار الخطوة» قد يغيّر حالة التطبيق المستهدف مثل الضغط أو الرجوع أو كتابة النص؛ استخدمه بحذر.
- زر الإيقاف المؤقت لا يلغي إيماءة بدأ تنفيذها بالفعل؛ يتوقف التقدم بعد اكتمال الإجراء الجاري. أثناء التقاط الشاشة أو تنفيذ إيماءة، تُخفى أزرار التحكم مؤقتًا لتفادي تداخلها مع الالتقاط أو النقر.
- إغلاق التطبيق بالقوة من إعدادات أندرويد أو قتل العملية من النظام لا يمكن اعتراضه لعرض حوار تأكيد، لكن التعديلات تُحفظ أثناء العمل، لذلك لا يعتمد حفظها على حوار الخروج وحده.

## البناء

يمكن البناء محليًا من جذر المشروع إذا توفرت Java 17 وGradle 8.13 وAndroid SDK 36:

```bash
gradle assembleDebug --no-daemon
```

يحتوي المستودع على GitHub Actions في `.github/workflows/build-apk.yml` لبناء APK تجريبي عند الدفع إلى فرعي `main` أو `master`، أو عند تشغيل الـ workflow يدويًا. ينتج الملف عادة في `app/build/outputs/apk/debug/app-debug.apk`.
